# Pesty code review — 2026-09-28

Two passes over the working tree (including the uncommitted restructure and Paste Stack / deletion changes): a **bug review** and a **performance review**. Findings come from reading the code; a handful were spot-verified by hand (marked ✅). Performance numbers are from a synthetic benchmark, not profiling of the real app.

---

## Part 1 — Bugs

### Build / test status

- **macOS app builds**, `scripts/build_app.sh` produces a universal ad-hoc-signed bundle.
- **macOS tests don't compile** ✅ — `ClipDeletionLedger.undoMostRecent` now returns an array (grouped undo), but `macOS/Tests/PestyTests/ClipDeletionLedgerTests.swift:28-29, 95-96` expect a single record. CI fails at "Test macOS app".
- **iOS builds; 1/52 tests fail** — `ClipboardImportTests.testImageWinsOverAccompanyingURL` (`iOS/Tests/ClipboardImportTests.swift:69`). `ClipboardReader.read` (`iOS/Pesty/Store/ClipboardWriter.swift:137-147`) picks up the URL-derived `pasteboard.string`, so image+URL becomes a link clip. Either a regression from 88b6df7 or a stale test.
- **Stray Xcode conflict copies** — `Xcode/Pesty.xcodeproj/project 2.pbxproj`, `project 2.xcworkspace/`, and `* 2.xcscheme` ×3 (likely iCloud Drive duplicates). `Xcode/.gitignore` un-ignores `Pesty.xcodeproj/**`, so `git add -A` would commit them. "Pesty iOS 2" references a non-existent `PestyTests` target.

### Sync data-loss risks (highest priority)

1. **iOS re-uploads the entire library on every launch** ✅ — `LocalLibraryPersistence.swift:247` encodes dates as `.iso8601` (whole seconds); `LibrarySyncing.swift:500-501, 515` fingerprints sub-second `timeIntervalSinceReferenceDate`. After restart every record's fingerprint differs → everything (incl. images) is re-uploaded and timestamps regress up to 1 s.
2. **Corrupt/undecodable iOS library wipes iCloud** — `LocalLibraryPersistence.load()` (`:27-30`) returns an empty library on any error; `diffAndEnqueue` (`LibrarySyncing.swift:183, 354-358`) then enqueues deletes for everything in the shadow. Also `LibraryStore.clearLocalLibrary` (`:361-371`) if `removeAll()` throws.
   - Mac equivalent: `ClipboardStore.load()` (`:1994-2001`) returns empty on decode failure and the next capture overwrites `store.json`.
3. **Losing a `serverRecordChanged` conflict drops the local edit** — `LibrarySyncing.swift:634-637` + `LibraryStore.swift:493-495` + `reconcileShadow` (`:427-428`) mark local as synced without re-enqueuing. Same on Mac `CloudSyncService.swift:537-538`.
4. **Placeholder boards beat real boards (iOS)** — `LibraryStore.swift:521-526` creates `PestyBoard(name: "Pinboard")` with `updatedAt = .now` (`PestyBoard.swift:28`); LWW then rejects the real board. Mac uses `.distantPast`.
5. **Asset cleanup deletes share-extension images** — `scheduleAssetCleanup` (`LibraryStore.swift:430-442, 535`) runs against in-memory state that hasn't reloaded the extension's clips.
6. **iCloud Drive (Mac↔Mac) merge is a union, not LWW** — `ClipboardStore.swift:2270-2276, 2299-2306`. Remote edits, renames, colors, pins, reorders are discarded and the stale copy is written back.
7. **Pinboard clip copied to History shares its UUID** — `promoteCopiedItem` (`ClipboardStore.swift:398-414`). Deleting the History card tombstones the Pinboard clip too on relaunch (`applyDeletionTombstones` runs before `migrateLegacySharedClipIDs`, `:2043` vs `:2050`).

### Uncommitted Paste Stack / deletion work

8. **Unreadable `stacks.json` blocks all deletes and Undo** — `stackStoreLoadFailed` (`ClipboardStore.swift:1690-1709`) is never cleared; `delete` (`:599`), `undoLastDelete` (`:712`), and "Delete all Stacks" (`:445`) all gate on `savePasteStacks`. `AppController.deleteBarSelection` ignores the Bool, so ⌫ silently does nothing.
9. **Last image in a Stack pastes the old clipboard after relaunch** — `takeEntry` clears entries → `persistActiveStack` → `pruneUnreferencedStackImages()` deletes the `stack-*.png` before it's pasted (`PasteSequence.swift:325-331`, `ClipboardStore.swift:422-423, 1753-1761`).
10. **Failed legacy Stack migration** freezes Stacks (every change reverted, `stack-*.png` leaked per add) and then `delete()`/`undoLastDelete()`/`refreshDeletionState()` persist the *unmigrated* stacks as if migrated (`ClipboardStore.swift:2012-2022, 1735-1737, 418-421, 599, 2081`).
11. **Remote CloudKit edit orphans `pendingStackRestorations`** — `ClipboardStore.swift:1360` → `ClipDeletionLedger.swift:152-158`.

### User-facing bugs (Mac)

- **Paste Stack hotkey pressed repeatedly pastes the last entry N times** ✅ — `PasteService.swift:207-231` queues a ⌘V per press, all fire on modifier release after the pasteboard holds only the newest entry. Earlier entries are consumed unpasted. The wait loop is also unbounded.
- **Link previews cached per host** ✅ — `LinkPreviewStore.swift:21-49`; every github.com link shows the first one's title/image.
- **⌘C in the bar search / rename field copies the selected clip** — `BarWindowController.swift:9-22`.
- **Hotkey recorder validates against the main shortcut only** — `HotkeyRecorderView.swift:52-58`, `HotKeyCenter.swift:53-69`; sequence == main is accepted and silently breaks one.
- **⇧↩ labelled "Paste as Plain Text" pastes original** — `AppController.swift:1851-1856` vs `ClipCardView.swift:613-617`.
- **Missing image file → ⌘V pastes previous clipboard** — `PasteService.swift:106-110`, `AppController.swift:763-773`.
- **Direct build without Accessibility leaves focus in Pesty** after the alert — `PasteService.swift:173-178`, `AppController.swift:1239-1254`.
- **Menu-bar "Open Pesty" shows stale shortcut** — `AppController.swift:301-306, 408-419`.
- **Global hotkey live during modal editor** — `AppController.swift:894-943`.
- **Extension transform queued behind background extension work** can paste seconds later into whatever is focused, or fail silently — `ExtensionHost.swift:30-33, 161`, `AppController.swift:776-801`.
- **Batch delete result ignored** — `AppController.swift:879`, `ClipCardView.swift:683` drop the Bool; failed save rolls back silently.
- **Excluded apps bypassed if bundle ID has `_` or no dot** — `ClipItem.swift:4-13`, `ClipboardMonitor.swift:155-160`.

### User-facing bugs (iOS)

- **Small widget tap doesn't open the clip** — `PestyWidget.swift:66-67, 99-100, 132` use `Link` in `.systemSmall`; needs `.widgetURL`.
- **One >50 MB image fails the whole share** and orphans already-written images — `ShareViewController.swift:53-56, 104`.
- **Shared file clips upload a dead iOS sandbox path** as `fileURLs` — `ShareViewController.swift:116-126`, `CloudRecordCodec.swift:16-19`.
- **`MacPestyStoreImporter` drops images, `updatedAt`, `lastUsedAt`, device name** and can overwrite the Mac's copy with an image-less clip — `MacPestyStoreImporter.swift:59-82`.
- **Sync failure status never visible** — `LibrarySyncing.swift:652-656` set `.failed`, immediately overwritten to `.ready` (`:664-665`, `:239`). `failedRecordDeletes` unhandled.
- **Zone deletion always re-uploads** even when the user chose "Delete iCloud data" — `LibrarySyncing.swift:620-623` (Mac too).

### Privacy / security

- **Privacy toggles wired to the wrong markers** ✅ — `ClipboardMonitor.swift:135-140`: "Ignore concealed" checks `AutoGeneratedType`; the real `ConcealedType` (password managers) is under "Ignore confidential".
- **Link previews GET the exact copied URL, on by default** — can consume one-time login / reset tokens.
- **Quick Look writes up to 500 clips as plaintext to `$TMPDIR`** on main and never cleans up — `QuickLookService.swift:38-57, 204-221`.
- **Deleted clips keep full content in iOS `library.json` forever** — `PestyLibrary.swift:279-286, 321-336`.
- **Runaway JS extension keeps running after timeout** — no JSC time limit; `while(true){}` burns a core until quit, each retry leaks a thread + VM (`ExtensionHost.swift:359-371, 386-432, 495-546, 640-645`). No sandbox escape found.

### Build / release

- **`scripts/build_mas.sh` omits `container-migration.plist`** — MAS users won't migrate their pre-sandbox library.
- **"Pesty macOS Development" scheme uses bundle ID `com.alvst.pesty`** + container migration → running it can move a developer's real direct-build library into the sandbox.
- CI `git diff --check` (ci.yml:67) is a no-op on a clean checkout; use `git diff --check origin/main...HEAD`.
- CI pins `OS=26.2` simulator — verify the runner has it, or drop the OS.
- iOS app `Info.plist` hardcodes `CFBundleVersion "1"`; extensions use `$(CURRENT_PROJECT_VERSION)`.
- Stale `Tests` exclude in `Xcode/project.yml:24-25`.
- `docs/llms.txt:10` garbled: "install Pesty, not Pesty."
- `iOS/README.md` doesn't mention `.widget`/`.share` App IDs or the app group.

The restructure itself is clean: all CI/release paths, scripts, schemes and doc links resolve; bundle IDs, app group and iCloud container are consistent; `CloudKitSchema.swift` copies are identical.

## Part 2 — Performance

### Measured (synthetic 5k-clip library: 5 × 5 MB text, 500 rich clips, 250 images)

| Operation | Cost |
| --- | --- |
| `store.json` size | ~70 MB |
| Full save (encode + atomic write), main thread | ~320 ms |
| Launch decode | ~574 ms |
| CloudKit fingerprint of whole library (MAS) | ~200 ms per save |
| TIFF→PNG on capture of a 5K image | ~160 ms (best case) |
| Full NSImage decode of 5K PNG | ~80 ms |

Already good: card strip is a `LazyHStack`; hosting view reused; polling only reads `changeCount`; ASCII search is fast and narrows; card text capped at 2,048 chars.

### Root cause 1 — one monolithic JSON file, saved on main after every change

- Mac `ClipboardStore.saveNow` (`:2116-2148`); delete/undo/applyRemote/mergeExternal call it synchronously.
- iOS `LibraryStore.persist()` (`:374-393`) reads + merges + re-encodes + writes under `NSFileCoordinator` on every mutation, including tapping Copy. No debounce. `JSONEncoder.pesty`/`JSONDecoder.pesty` allocate per access.
- iCloud Drive sync re-uploads the full file after every copy.
- iOS widget (`PestyWidget.swift:45-47`) decodes the whole library in a ~30 MB process to show ≤6 clips; will blank out on big libraries.
- Share extension decodes + re-encodes the whole library to append a clip.

**Fix:** move `text` > ~64 KB, `rtfData`, `htmlData` into per-clip sidecar files (like images) → metadata file ~2–3 MB. Snapshot on main, encode/write on a background queue, debounce. Widget reads a tiny `widget-snapshot.json`; share extension writes to an `inbox/` dir.

### Root cause 2 — sync re-hashes everything

- `desiredRecords()`/`fingerprint` hash full text + freshly base64'd RTF per save (both platforms). `record(for:)` rebuilds it per record → O(N²) initial upload/re-upload.
- iOS fetch batches do full merge + persist + reconcile + shadow write per batch; assets copied and re-hashed on main.
- Mac `applyRemote` (`:1342-1481`) is O(M·N) with per-record system-field file writes on main.

**Fix:** fingerprint from `(id, updatedAt, container, deleted, imageHash)` or cache by `(id, updatedAt)`; dirty-ID set from the store; build one lookup per batch; apply fetches once at `didFetchChanges`, decode off main.

### Root cause 3 — no caching in card rendering

- Image cards call `NSImage(contentsOf:)` / `UIImage(contentsOfFile:)` inside `body` at full resolution (Mac `ClipCardView.swift:280-305, 439-445`; iOS `RichClipPreview.swift:12-13, 86-87, 131-134`).
- RTF parsed in full every render (Mac `ClipPreviewViews.swift:95-102` + contrast walk; iOS `RichClipPreview.swift:194-202`).
- Per-render `RelativeDateTimeFormatter`/`DateFormatter` (`Theme.swift:208-221`), `NSWorkspace.icon(forFile:)`, `Contrast.adjustSurface`.

**Fix:** `NSCache` of downsampled thumbnails via `CGImageSourceCreateThumbnailAtIndex` loaded in `.task(id:)`; truncate RTF to preview length and parse off main with a cache; static formatters; cache adjusted colors and icons.

### Root cause 4 — over-broad invalidation

- Any extension result redraws every card (`ExtensionResultStore.outcomes` single observed dict).
- Arrow keys re-evaluate the whole `BarView` body and enumerate all items; passing `index` into cards re-renders all on insert.
- Every card reports its frame via GeometryReader on every scroll frame (`BarView.swift:437-443`).
- `visibleItems` with saved Stacks is O(clips × stack entries) uncached, read many times per keypress (`ClipboardStore.swift:282-289`).
- iOS: `syncStatus` flips re-sort and re-render the whole library; `updateSyncStatus` assigns even when unchanged.

### Other

- **Capture on main** (`ClipboardMonitor.swift`): TIFF→PNG, SHA-256, PNG write, eager RTF/HTML reads; PNG written before dedupe.
- **Deletion ledger never pruned**, linear lookups; `clearHistory` of 5k is O(N·L); `cloudRetentionExcludedIDs` grows forever and is rewritten per capture.
- **iCloud Drive watcher** re-reads the 70 MB file after our own writes; remote merge decodes on main, O(n²) pinboard merge, unconditional `saveNow()`, non-deterministic sort → possible Mac↔Mac ping-pong.
- **Non-ASCII search** falls back to `range(of:.caseInsensitive)` — ~2 s/keystroke with big clips; keyword sweep bumps `contentVersion` per pair, invalidating the search cache.
- **Extension keyword sweep** spins up a new Thread + JSVirtualMachine per clip and rescans from the start each chunk.
- **`deleteImageFile`** scans the whole library per call, called in loops.
- `LinkPreviewStore` keeps full-size images forever; paste writes `NSImage` (TIFF) instead of stored PNG bytes.
- Held arrow keys stack spring scroll animations; per-card `.shadow` over composited content.

### Suggested order

1. **Quick wins:** only `scheduleSave()` in `applyHistoryPolicy()` when something was removed (`ClipboardStore.swift:392`, called on every bar open from `AppController.swift:623`); make iOS encoder/decoder static; guard `syncStatus` assignment; add `timer.tolerance`.
2. **Thumbnail cache + capped RTF parsing** on both platforms.
3. **Background, debounced saves.**
4. **Sidecar storage for large payloads** (also fixes widget/share-extension memory).
5. **Incremental sync fingerprints.**

Items 3–5 touch the same code as the sync data-loss bugs in Part 1 — worth tackling together.

## Overall assessment

A genuinely good, native app with thoughtful features (5-minute undo, source-app colours, Paste Stacks, a tightly bounded extension API) and unusually well-commented code. The iOS companion is careful about file protection and app-group coordination.

Weak spots are structural: `ClipboardStore.swift` (~2,400 lines) and `AppController.swift` (~2,000 lines) juggle many interacting flags; sync is the riskiest area (timestamp precision, conflict handling, "empty means delete everything"); and the new Stack persistence keeps state in five places with hand-rolled rollback, where most new bugs live.

**Recommended first steps:** fix the failing tests, add a guard that refuses to sync deletions when the local library failed to load, fix the iOS date-precision re-upload, correct the privacy toggle mapping, then the Stack bugs (8–9).
